title: 'Mirror'
description: 'Replicate agent session files across machines to a hub — the archive'
---

**Mirror** replicates your agents' session files across machines into one hub, so the
archive of everything that ever happened follows you wherever you work.

Say Claude Code writes session logs to `~/.claude/projects` on your laptop and Codex
writes its own on a VPS. `uc mirror` keeps both replicated to a central hub, so an agent
on any machine can grep or semantically search every session — not just the ones
written locally.

<Note>It's a **mirror, not a bidirectional sync** — a one-way replica (laptop →
hub) of files the agents already wrote on disk. It replicates; it never writes
context. To write, use [`uc context`](/concepts/contexts).</Note>

<Note>`uc sync` still works as an alias for `uc mirror` — the old verb keeps
running.</Note>

## Files are the archive

Mirror moves **files** — the first of the three [primitives](/concepts/overview) it is
responsible for. Files are raw session artifacts: transcripts, exports, markdown
dumps. They are the **archive** you search over, distinct from live
[contexts](/concepts/contexts) and from the [events](/concepts/events) status board.

Under the hood, mirror is fs-first orchestration over [Mutagen](https://mutagen.io)
running `--mode=one-way-replica`. You declare which local directories to mirror;
Mutagen replicates them to the hub in one direction. The `mutagen` binary must be
on your `PATH` — `uc doctor` checks for it.

## Sources

A **source** is a named local directory you want mirrored. You add one per agent's
session directory.

```bash bash
uc remote set user@vps:/home/alice/.ultracontext   # set the hub (your central remote)
uc mirror source add claude ~/.claude/projects      # mirror Claude Code sessions
uc mirror source add codex ~/.codex/sessions        # mirror Codex sessions
uc mirror start                                      # bring enabled sources online
```

The hub is your [remote](/concepts/remote) — the one central machine `uc` routes
to, configured once by [`uc remote set`](/fundamentals/cli#remote-commands). Mirror
uses its SSH leg; `uc mirror` only reads it, never sets it.

| Subcommand | What it does |
|---|---|
| `source add <name> <path>` | Add or update a source (`--disabled` to add without starting) |
| `source list` | List configured sources |
| `source remove <name>` | Remove a source (terminates its session); `--purge-remote` also deletes its hub workspace dir |
| `source enable <name>` / `source disable <name>` | Toggle a source, then start / pause its session |
| `start` / `stop` | Start / pause mirroring for enabled sources |
| `status` | Show live mirror session status |
| `list` | List configured sources with their mirror state |
| `reset` | Terminate owned sessions and restart enabled sources |

<Warning>`source remove --purge-remote` is **destructive** — it deletes the
source's mirrored files on the hub. The local source directory is left
untouched. There is no interactive confirm; the flag is the confirm.</Warning>

## Ignore files

Mirror never replicates everything in a source dir blindly. Patterns from two
`.ultracontextignore` files under `~/.ultracontext/ignores/` become repeated
`--ignore=<pattern>` flags on the underlying Mutagen session:

| File | Scope |
|---|---|
| `~/.ultracontext/ignores/.ultracontextignore` | **Global** — applies to every source |
| `~/.ultracontext/ignores/<source>/.ultracontextignore` | **Per-source** — applies to that source only |

The global file is **seeded with sensible defaults on first use** — source
control (`.git/`), build and dependency dirs (`node_modules/`, `target/`,
`dist/`, `build/`, `.next/`, `.cache/`), runtime logs (`logs/`, `*.log`),
browser/electron caches (`Cache/`, `GPUCache/`, `Code Cache/`, `blob_storage/`),
SQLite WAL/SHM sidecars (`*.sqlite-wal`, `*.sqlite-shm`), and `.DS_Store`. Edit,
comment out, or extend any line; non-blank, non-`#` lines are the patterns.

```bash bash
$EDITOR ~/.ultracontext/ignores/.ultracontextignore   # edit global rules
uc mirror reset                                       # re-apply after edits
```

<Note>An existing `~/.ultracontext/config.toml` (the 2.0 layout) is
**auto-migrated** to `config.json` the first time `uc mirror` runs. The original
is kept as `config.toml.migrated` — never deleted — so you can remove it
yourself once you're happy.</Note>

## Hub workspace layout

On the hub, mirrored files land under a per-host, per-source tree. Every machine
gets its own namespace, so nothing collides:

```text
<hub-root>/
  workspace/
    <host>/                 # one dir per machine (host id)
      <leaf>/               # one dir per source (the leaf of its local path)
        ...mirrored files
```

The per-source dir is the **leaf of the source's local path**, not the source name.
So the `claude` source (`~/.claude/projects`) lands under `projects/`: sessions from
your laptop and from your mini live side by side as `workspace/laptop/projects/` and
`workspace/mini/projects/` — an agent on the hub sees the union of every machine's
archive.

## What Mirror is not

Mirror replicates **files**. That's all. It is deliberately dumb.

- It is **not a store you write to.** Mirror only replicates files the agents
  already wrote on disk — it never authors content. The store an agent reads and
  writes is a [context](/concepts/contexts).
- It is **not events.** Mirror doesn't tell you *what changed, now* — that's the
  [status board](/concepts/events). A [driver](/concepts/drivers) emits an event
  when it mirrors a file; mirror itself just moves bytes.
- It is **not contexts.** Mirror replicates raw artifacts, not versioned conversational
  state. Live state an agent reads and writes is a [context](/concepts/contexts).

<Tip>Pairing matters: a [driver](/concepts/drivers) does a bounded sync of an
external app's sessions into files, then emits one `*.session.updated`
[event](/concepts/events) per changed file. Mirror is the muscle; events are the
signal.</Tip>
