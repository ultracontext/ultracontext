title: 'Phone-triggered sync: the iOS relay'
description: 'Open Claude on your phone — your laptop agent knows the conversation'
---

The **iOS relay** is a recipe that turns "I opened Claude on my phone" into a signal
your laptop agents can act on, with no app, no cloud account, and no phone-to-laptop
coupling.

Concretely: you open the Claude app on your iPhone. A few seconds later, the laptop
agent you talk to tails the [event log](/concepts/events), sees a fresh
`claude.session.updated`, reads the mirrored transcript file, and knows what you and
Claude just discussed on your phone. This guide documents the real system running on
the author's infrastructure, as a reproducible recipe.

<Note>**Contract v1** — the envelope (`uc.event.v1`) and driver manifest are final
and run on real infrastructure today. The `uc driver` / `uc event` CLI surfaces ship
in an upcoming release; core implementation is in progress.</Note>

## Why this shape

Before the steps, the reasoning — it's the part you'll reuse for any system:

- **The phone only sends a signal.** A phone can't run the sync itself: it has no
  logged-in *desktop* browser and no real filesystem to mirror sessions into. So it
  does the one thing it can — fire a tiny "I opened the app" ping.
- **A relay host centralizes reachability.** The phone talks to **one always-on
  server** it can always reach. The server, not the phone, knows how to reach your
  Mac. This removes phone→Mac coupling: your laptop can sleep, move networks, change
  IPs, and the phone never has to care.
- **The driver runs where the logged-in browser is.** The actual web sync happens on
  the Mac — the only machine with an authenticated Claude session and a filesystem.
  That's the [driver's](/concepts/drivers) job: it is the side-effect boundary.
- **Bounded sync keeps the hook cheap.** App-open fires constantly. The driver syncs
  only recent sessions (`--limit 10`), never a full crawl, so the lifecycle hook stays
  fast and idempotent.
- **Events stay small; files hold the weight.** The event carries `counts` and a
  `payload_ref` to a markdown file — not the transcript. Consumers read the file only
  if it's relevant, on their own schedule.

## Architecture

```text
 iPhone                  always-on server            Mac (logged-in browser)
┌────────────┐  ssh    ┌──────────────────┐  ssh   ┌─────────────────────────┐
│ iOS        │ ──────► │ ios_sync_relay    │ ─────► │ uc driver run           │
│ Shortcut   │         │ {app}×{opened|    │        │   claude-web opened     │
│ (on app    │         │  closed|poll} →   │        │     │                   │
│  open/     │         │  ssh BatchMode    │        │     ▼                   │
│  close)    │         │  to the Mac       │        │ bounded web sync        │
└────────────┘         └──────────────────┘        │   (--limit 10)          │
                                                    │     │                   │
                                                    │     ├─► markdown files  │
                                                    │     └─► uc.event.v1 ────┼──► hub log
                                                    └─────────────────────────┘    │
                                                                                    ▼
                                                              any agent's pre-turn consumer
                                                              (e.g. the Hermes plugin) tails
                                                              the log → reads file:// gist →
                                                              injects a provenance-labeled signal
```

## Steps

<Steps>
  <Step title="Install the driver on the Mac">
    The Mac is where the logged-in browser lives, so the driver lives there. Create
    `~/.ultracontext/drivers/claude-web/driver.toml` with the lifecycle verbs pointing
    at your sync script:

    ```toml ~/.ultracontext/drivers/claude-web/driver.toml
    name = "claude-web"
    version = "0.1.0"
    type = "external-app-sync"
    runtime = "python"

    [capabilities]
    events = true
    artifacts = true
    bounded_sync = true
    requires_logged_in_browser = true

    [commands]
    opened = "~/.hermes/scripts/claude_sync.py opened --source ios_shortcut --limit 10"
    closed = "~/.hermes/scripts/claude_sync.py closed --limit 10 --settle-seconds 5"
    poll   = "~/.hermes/scripts/claude_sync.py poll --limit 1"
    status = "~/.hermes/scripts/claude_sync.py status"
    doctor = "~/.hermes/scripts/claude_sync.py doctor"
    ```

    The script does a bounded sync, mirrors changed sessions to markdown, and emits a
    lifecycle event plus one `claude.session.updated` per change. Building that script
    is the [Write a driver](/guides/write-a-driver) guide. Verify it on the Mac itself
    first:

    ```bash on the Mac
    uc driver run claude-web poll
    uc event tail --limit 3
    ```
  </Step>

  <Step title="Install the relay script on the server">
    The relay is a ~40-line bash script that maps `{app} × {event}` to an SSH call into
    the Mac running the stable driver verb. It holds **no secrets** and **no app
    knowledge** — just routing.

    ```bash ~/.ultracontext/scripts/ios_sync_relay
    #!/usr/bin/env bash
    set -euo pipefail

    # which app + which lifecycle event the phone is reporting
    APP="${1:?usage: ios_sync_relay {chatgpt|claude} {opened|closed|poll}}"
    EVENT="${2:?usage: ios_sync_relay {chatgpt|claude} {opened|closed|poll}}"

    # the Mac that has the logged-in browser (override via env)
    MINI_HOST="${MINI_HOST:-fabios-mac-mini}"   # reachable over Tailscale
    MINI_USER="${MINI_USER:-fabio}"
    UC_BIN="/Users/${MINI_USER}/.local/bin/uc"

    # map the app to its driver
    case "$APP" in
      claude)  DRIVER="claude-web"  ;;
      chatgpt) DRIVER="chatgpt-web" ;;
      *) echo "unknown app: $APP" >&2; exit 2 ;;
    esac

    # only forward the bounded lifecycle verbs
    case "$EVENT" in
      opened|closed|poll) CMD="$EVENT" ;;
      *) echo "unknown event: $EVENT" >&2; exit 2 ;;
    esac

    # one non-interactive SSH hop into the Mac, running the stable driver verb
    exec ssh -o BatchMode=yes "${MINI_USER}@${MINI_HOST}" \
      "${UC_BIN} driver run ${DRIVER} ${CMD}"
    ```

    Make it executable: `chmod +x ~/.ultracontext/scripts/ios_sync_relay`. Test the
    full server→Mac hop by hand:

    ```bash on the server
    ~/.ultracontext/scripts/ios_sync_relay claude poll
    ```
  </Step>

  <Step title="Create the iOS Shortcut">
    On the iPhone, use the **Shortcuts** app's automation to fire the relay one-liner:

    1. **Automation → App.** Pick the Claude app, trigger on **Is Opened** (add a
       second automation for **Is Closed**). Turn **Run Immediately** on (no
       confirmation prompt).
    2. **Action: Run Script Over SSH.** Point it at your always-on **server** (host,
       user, and an SSH key — see security below).
    3. **Script:** the single relay command for this automation:

       ```bash Is Opened
       ~/.ultracontext/scripts/ios_sync_relay claude opened
       ```

       ```bash Is Closed
       ~/.ultracontext/scripts/ios_sync_relay claude closed
       ```

    The phone never touches the Mac. It only ever talks to the server, which fans out.
  </Step>

  <Step title="Verify end to end">
    Open the Claude app on your phone, talk to it, close it. Within a few seconds, on
    your laptop:

    ```bash on the laptop
    uc event tail --limit 5
    ```

    You should see the lifecycle event followed by one update per changed session:

    ```json
    {"schema_version":"uc.event.v1","event_id":"evt_claude_closed_1780467902971_88045","kind":"claude.app.closed","source":"claude-web-ios-shortcut","subject":"claude:app:ios","occurred_at":"2026-06-03T06:25:02.978Z","host":"fabios-mac-mini","priority":50,"ok":true,"privacy":"metadata_only","counts":{"listed":10,"candidates":0,"fetched":0,"synced":0,"changed_sessions":0},"labels":{"app":"claude","platform":"ios","trigger":"closed"},"error":null}
    ```

    The `claude.session.updated` events carry a `payload_ref` pointing at the mirrored
    markdown file on the Mac — that's the transcript your agent can read.
  </Step>

  <Step title="Consume it from your agents">
    The events are now in the hub log and the files are in UC-controlled roots. The
    last mile is making an agent *act* on them before each turn — tail the log,
    compute the delta since its last turn, read a bounded gist from the local
    `file://` payload, inject a provenance-labeled signal. That's its own guide:

    <Card title='Make your agents aware of each other' icon='radio' href='/guides/agent-awareness'>
        The consumer side — and the Hermes plugin as a worked example.
    </Card>
  </Step>
</Steps>

## Security notes

- **BatchMode SSH keys, no passwords.** Every hop uses `ssh -o BatchMode=yes` with
  key auth so it never prompts. Scope the keys narrowly (a dedicated key per hop;
  consider `command=` restrictions in `authorized_keys`).
- **Private network reachability.** Keep the phone→server→Mac path on a private
  overlay (the author uses **Tailscale**). The always-on server is the only host that
  needs to be broadly reachable; the Mac stays private.
- **No secrets in the manifest.** The `driver.toml` and the relay script carry zero
  cookies, tokens, or headers. The Claude session auth lives only in the logged-in
  browser on the Mac and is resolved at runtime by the sync script.
- **`privacy: metadata_only` by default.** Events carry counts and a `payload_ref`,
  never transcript bodies. The heavy content stays in files behind a `file://`
  reference your consumer reads deliberately.
