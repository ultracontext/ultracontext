---
title: 'Make your agents aware of each other'
description: 'Tail the event log before each turn so every agent knows what just changed'
---

**Agent awareness** is the consumer side of [events](/concepts/events): anything that
does work emits a small fact, and every agent tails the log before each turn to learn
what changed elsewhere — on another machine, in another session, from another agent.

Concretely: your build agent finishes a run and emits `agent.run.completed`. Minutes
later, on a different machine, you ask a second agent an unrelated question. Before it
answers, it tails the log, notices the completed run since its last turn, and folds
that into its reply — labeled as external. Two agents, never directly connected, stay
in sync through the log.

<Note>**Available today** — the envelope (`uc.event.v1`) and the `uc event` CLI
surface (`emit` · `tail` · `status` · `flush` · `commit`) ship in `ultracontext`
now, so the consumer pattern below runs end to end, as does the
[`uc driver`](/concepts/drivers) surface that most events come from.</Note>

## The two halves

Awareness is a producer and a consumer sharing one log:

```text
do work ──► uc event emit ──► hub log ──► uc event tail ──► inject signal ──► turn
(producer)                                (consumer, pre-turn)
```

You write the producer side once per kind of work, and the consumer side once per
agent. The log is the only coupling between them.

## Emit from anything that does work

When something finishes — a run, a test pass, a deploy — emit one small event. Keep
it a *fact*, not a payload: heavy output goes in a file the event points at.

```bash bash
uc event emit \
  --kind agent.run.completed \
  --source build-agent \
  --subject agent-run:build:run_abc123 \
  --run-id run_abc123 \
  --ok true \
  --privacy metadata_only \
  --payload-ref file:///Users/fabio/.uc/runs/run_abc123.md \
  --payload-hash sha256:... \
  --count tests_passed=53 \
  --label project=ultracontext
```

That commits a `uc.event.v1` envelope to the hub log. The transcript or summary lives
in the `payload_ref` file; the event itself stays small.

## Tail before each turn

Each agent reads a bounded window of recent events right before it responds:

```bash bash
uc event tail --limit 20 --json
```

`tail` always emits **line-delimited JSON** (one envelope per line) — in both human
and `--json` modes — the stable consumer contract regardless of how the log is stored
underneath. A pre-turn hook parses those lines and decides what, if anything, to
inject.

## The delta-cursor pattern

Don't re-inject the same 20 events every turn — that's noise, and it grows. Keep a
**per-session cursor** (the last `event_id` you injected) and only surface what's
**new** since the agent's previous turn:

```text
turn N    : cursor = evt_05    tail → [evt_03 … evt_08]    inject {evt_06, evt_07, evt_08}, cursor ← evt_08
turn N+1  : cursor = evt_08    tail → [evt_06 … evt_09]    inject {evt_09},                cursor ← evt_09
```

The cursor is per-agent-session, so two agents tailing the same log each get their own
"what's new for me". This is exactly what the Hermes plugin does — one cursor per
Hermes session.

## Read bounded gists from local files only

For relevant `*.session.updated` (or `*.run.completed`) events, read a **bounded
excerpt** from the `payload_ref` — and only when it's a **local `file://`** path:

- Never inline raw transcripts, prompts, tokens, cookies, headers, or signed URLs.
- Never fetch non-local or non-`file://` refs into the turn.
- Cap the excerpt (a prefix of a few hundred chars), not the whole file.

The event told you *that* something changed; the file lets you peek at *what* — on
your terms, bounded.

## Fail open

Awareness is a nice-to-have layered on a turn, never a dependency of it. If anything
goes wrong, **inject nothing and let the turn proceed**:

- `uc` is missing on PATH → inject nothing.
- `uc event tail` returns non-zero or times out → inject nothing.
- No new events since the cursor → inject nothing.

A consumer must never block or break the agent it augments.

## Label provenance

Injected signals are *not* the current conversation — they're external facts from
another machine or session. Always attribute them so the agent doesn't confuse them
with what the user just said:

```markdown injected
## UltraContext activity signal
Recent relevant session updates (external — phone/other-agent sync, not this chat):
- New Claude session since last turn | title=Dia ruim | payload_ref=file:///…/abc123.md | gist=…
```

## Worked example: the Hermes plugin

The Hermes plugin is a real, shipping consumer that follows every rule above. It is a
**consumer plugin, not an ingestion driver** — it reads events, it never syncs apps.

- **Hook: `pre_llm_call`** — runs before every model call and can return
  `{"context": "..."}`, which Hermes appends to the current turn. (It deliberately
  does *not* use `agent:start` / `on_session_start`; those are init hooks, not
  per-turn injection.)
- **Source command:** `uc event tail --limit <n>`.
- **Delta cursor:** one per Hermes session — injects only the event delta since that
  session's previous turn.
- **Bounded gist:** for relevant `*.session.updated` events with local `file://`
  payloads, reads a bounded prefix; full excerpts are opt-in and still capped.
- **Fail-open:** `uc` missing, non-zero, timeout, or no events → injects nothing.
- **Provenance:** explicitly tells the agent injected payloads are external app sync,
  not the current chat.

Tune it with environment variables:

| Variable | Default | Max | Purpose |
|---|---|---|---|
| `ULTRACONTEXT_CLI` | resolves `~/.local/bin/uc`, then PATH | — | Explicit path to `uc`. |
| `ULTRACONTEXT_HERMES_EVENT_LIMIT` | `20` | `50` | Events to tail per turn. |
| `ULTRACONTEXT_HERMES_TIMEOUT_SECONDS` | `3` | `30` | Command timeout. |
| `ULTRACONTEXT_HERMES_ENABLED` | `true` | — | Set `false` to disable injection. |
| `ULTRACONTEXT_HERMES_INCLUDE_PAYLOAD` | `false` | — | Include a bounded sanitized excerpt from local `file://` payloads. |
| `ULTRACONTEXT_HERMES_PAYLOAD_CHARS` | `1800` | `6000` | Excerpt length cap. |

The result: open Claude on your phone (via the [iOS relay](/guides/ios-relay)), and
your laptop's Hermes session — without you saying a word — opens its next turn knowing
what you discussed.
